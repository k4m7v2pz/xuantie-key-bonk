# 玄铁重写规划（KeyBonk C++ → 玄铁）

> 本文是把当前 C++17/Win32 版 KeyBonk 重写为玄铁语言的前期规划，依据已查证的 C++ 基线（见《架构概览.md》）、玄铁音频库（`xuantie-audio-player`）、玄铁渲染库（raylib 桥）与语言内建能力整理。
> 标注「待实测」的项，指尚未在玄铁工程里跑过、需搭骨架时验证；本文不把它们写成已成立。
> 平台决策（已敲定）：**先在本机 macOS arm64 开发调试（方案 A），音频后端现成可用；Windows 回归后置。**

## 1. 为什么不是"原样移植"

C++ 版的核心是 Windows 低级全局钩子（`WH_KEYBOARD_LL` / `WH_MOUSE_LL`）+ Win32 分层透明置顶窗口。这两样在玄铁/渲染库里都没有等价物，因此本次是**在 macOS 上重新实现一套**，而不是把 Windows 代码翻译过去。音频、绘图、文件读写这些可以直接复用或对齐。

## 2. 能力对照（C++ 现状 → 玄铁可得）

| C++ 现状能力 | 玄铁侧来源 | 结论 |
|---|---|---|
| 预加载 wav、立即混音播放（yumo `preloadAudio/addAudio`） | `xuantie-audio-player`：`预加载(路径)→成功(id)/失败(原因)`、`播放(id)`、`播放文件(路径)` | 现成，可对齐 |
| 后台异步预加载 + `readySign` 标志 | 音频库 `预加载()` 为**同步返回**；玄铁有 `异步{}` 线程池 | 改为同步预加载，或用 `异步{}` 包一层；无需 readySign |
| 键盘静音 / 鼠标静音（钩子层判断后不调用播放） | 调用前自行判断静音标志 | 现成；**不依赖音频库的全局静音（该接口是占位不生效）** |
| 窗口内按键/鼠标读取 | 渲染库 `键按下?/键刚按下?/鼠标按下?/鼠标刚按下?/鼠X/鼠Y` | 仅**窗口焦点内**输入，非全局 |
| 全局键盘/鼠标钩子（核心触发） | 渲染库、标准库均无 | **最大缺口**，macOS 需 CGEventTap + 辅助功能权限，见 §5 |
| 无边框窗口、客户区拖动 | 渲染库 `设窗口无边框`、`拖拽窗口` | 现成 |
| 置顶（TOPMOST）、点击穿透（WS_EX_TRANSPARENT）、窗口透明 | 渲染库未提供 | 缺口，见 §5 |
| 托盘图标、右键/托盘系统菜单 | 渲染库未提供 | 缺口，见 §5 |
| 背景图（PNG 缩放、alpha 绘制） | 渲染库 `加载纹理/绘纹理/绘纹理Ex` | 可做，缩放/圆角由渲染库接口提供 |
| config.ini 读写（win-x/win-y/mute/mute-m/lib） | 内建 `文件.读/写/存在?`，INI 需自写解析 | 可行，无现成 INI 库 |
| 递归扫描音频库目录、纯数字 0–255 命名 wav | 内建 `执(shell)`（`ls -1`）/ FFI；递归过滤自写 | 可行，遍历 API 待实测 |
| 鼠标音效随机选 `{74,77,78,84}` | 渲染库 `取随机数(min,max)` | 现成 |
| UTF-8 追加日志 log.txt | `文件.写` 自实现追加 | 可行 |
| 自身可执行文件目录、相对路径转绝对 | FFI `xt_self_path()` + 字符串处理 | 可行，待实测 |

### 2.1 音频库 API 与 KeyBonk 用法对齐

| C++ 调用 | 玄铁音频库 | 备注 |
|---|---|---|
| `yumo::preloadAudio(路径, &ready)` | `音频.预加载(路径)` → `成功(预加载ID)` / `失败(原因)` | 同步，无 readySign |
| `yumo::addAudio(preloadId)` | `音频.播放(预加载ID)` | 无音量参数，原代码也未传 |
| 退出释放 | `音频.关闭音频()` | 退出前调用 |

音频库明确**不提供**（KeyBonk 也用不到）：实例级音量/暂停/位置、播放完成回调、单个音效强停、全局静音/音量实际生效。

## 3. 目录组织（已定）

仓库根的 C++ 工程（`src/`、`include/`、`resource/`、`Makefile`、`installer.iss` 等）**原样保留不动**；玄铁工程放独立子目录 `app/`，避免与 C++ 构建混淆：

```
xuantie-key-bonk/
├── src/  include/  resource/  Makefile  installer.iss …   # C++ 现状，保留
├── docs/                                                  # 文档（本文在此）
└── app/                                                   # 玄铁工程
    ├── xtl.json
    ├── 主函数.xt（入口）
    ├── 模块*.xt（钩子/窗口/配置/扫描/播放入口拆分）
    └── tiepm_modules/                                     # 依赖落地（渲染桥等，已 gitignore）
```

> 玄铁命令（`xtl add/run/build`）在 `app/` 子目录内执行。

## 4. 玄铁侧模块拆分（目标形态）

| 玄铁模块（建议） | 职责 | 对应 C++ 模块 |
|---|---|---|
| 入口（主函数.xt） | 初始化音频设备、读配置、起预加载、进入主循环、收尾释放 | main.cpp |
| 配置 | config.ini 读/写（位置、键盘/鼠标静音、音频库路径） | config.ini 处理、global |
| 音频扫描 | 递归列目录、纯数字 0–255 命名 wav、预加载并建 vk→预加载ID 表 | preloadAudio / audioPlay.cpp |
| 播放入口 | 按 vkCode 查表，静音判断后 `音频.播放(id)`；鼠标随机取列表 | audioPlay.cpp / mouse_hook.cpp |
| 输入（全局） | macOS CGEventTap 监听，回调到播放入口（缺口，见 §5） | keyboard_hook / mouse_hook |
| 窗口 | 无边框窗口、背景纹理、拖动、自绘菜单/静音开关（置顶/穿透/托盘见 §5） | main_window / background |
| 日志 | UTF-8 追加写 | debug.cpp |

## 5. 关键技术缺口与选型（macOS）

### 5.1 全局输入监听（最大风险）

- C++ 靠 Windows 低级钩子在**任意应用聚焦时**都能听到按键。macOS 无等价钩子，需用 Core Graphics 的 **CGEventTap** 全局监听，并向用户申请**辅助功能（Accessibility）权限**。
- 玄铁渲染库只做窗口内输入，不提供全局事件；CGEventTap 回调需要 C 侧桥接（类似现有 `渲染桥.c` 的 FFI 做法），这是独立攻坚项。
- **降级路径**：先在渲染窗口聚焦内用 `键按下?` 触发出声（验证音频链路），再单独攻 CGEventTap 全局监听。

### 5.2 窗口：置顶 / 点击穿透 / 透明

- 渲染库提供无边框、拖动、清背景带 alpha，但**未提供 topmost 置顶、点击穿透、系统级透明合成**。
- 第一版可先做一个普通无边框小窗显示背景/状态；置顶穿透等在 macOS 上需查 raylib 原生能力或另补桥接，列入后续增强，不阻塞出声主链路。

### 5.3 托盘与菜单

- 渲染库无系统托盘、无原生右键菜单。第一版用窗口内自绘按钮/菜单替代；系统托盘属增强项。

## 6. 依赖引入方式（M0 实测记录）

工具链模块解析规则（读 `xuantie_compiler/编译.xt` 确认）：

- `引 "渲染"` 这类**裸包名**只查两处：铁铺已安装 `~/.tiepm/已安装/<名>/<名>.xt`，兜底编译器自带 `lib/<名>/<名>.xt`；**不扫项目 `tiepm_modules/`**。
- `引 "./xxx.xt"` 相对路径按源文件目录解析。
- `xtl add` 写进 `xtl.json`/`xtl.lock` 并落地 `tiepm_modules/`，主要服务构建链接；裸包名别名能否 `引 "音频"` 取决于是否已装进铁铺或为自带库。

M0 实测结果：

1. `xtl add 音频 <git url>` 能整仓 clone 到 `tiepm_modules/音频/`，但主模块 `引 "音频"` 报"无法解析铁铺包引用"——音频库未发布到铁铺注册中心，裸包名走不通。
2. **两级相对路径可用（M0 实测成功）**：`引 "../../xuantie-audio-player/音频库.xt" 予 音频`（两工程并列于 `Code.localized/`），经音频库 `预加载合成(440,300)` → `播放`（实例=1）→ `关闭音频()` 全通。注意相对路径基准是工程上级目录而非源文件目录，`../` 一级会解析错。
3. `--path` 本地路径无先例，未深入。
4. 音频库内部 `引 "渲染"` 依赖裸包名解析到自带/铁铺渲染；KeyBonk 工程需自身渲染依赖。
5. **vendored 自包含（B:2）当前受阻**：纯净 `音频库.xt` 复制进 `app/` 后，库内设备初始化报 `Failed to initialize playback device`；对照：主模块直连 `R.初始化音频()`、同目录最小库（含全部顶层状态）均成功，仅完整库在本目录失败、外部并列引用却成功。属编译器/模块绑定层问题，已写 /tmp 交接转语言维护，未入库。

> 结论：新工程直连渲染基线已通；经音频库接入当前可用**外部并列两级相对路径**（第2条，已验证）。vendored 自包含待语言维护闭环，铁铺发布为最终目标；M1 先用外部相对路径推进，不阻塞。

## 7. 分阶段路线

- **M0 骨架 + 音频最小验证**（已完成）：`app/` 骨架建成；新工程内纯渲染库 `初始化音频()` → `合成音效(440,300)` → 播音效 → 关闭音频，本机 macOS arm64（Core Audio/miniaudio，48kHz 立体声）实测成功、句柄=1。早期"新工程初始化失败"已由语言维护闭环：根因是旧分发包固定链 `libraylib.a`、缺 macOS `libraylib.darwin-arm64.a`，新分发包（lock 二进制哈希 `sha256:2a7d013b…`，26.10.19）按平台选库修复。
- **M1 扫描与预加载表**：递归扫描音频库目录，纯数字 wav 预加载，建 vk→预加载ID 映射；同步/异步预加载定版。
- **M2 触发出声（降级版）**：窗口内按键/鼠标映射到播放入口，验证"按键→查表→播放"全链路。
- **M3 全局输入攻坚**：CGEventTap + 辅助功能权限，实现任意聚焦下出声；补鼠标随机音效。
- **M4 窗口/配置/打磨**：无边框窗口与背景、config.ini 持久化、日志、静音开关；置顶/穿透/托盘按 §5 增强。

## 8. 风险与待验证清单

- CGEventTap 在玄铁 FFI 下的回调可行性、辅助功能权限申请流程（M3 前需单独验证）。
- 音频库引入：裸包名需铁铺注册中心（音频库未发布），M1 前在相对路径/本地桥接/铁铺发布中定版。
- （已闭环）新工程 `初始化音频()` 失败系旧分发包缺 macOS 平台库，新分发包修复，勿再排查。
- 渲染库坐标系抽象三 API（取缩放系数/转像素/转逻辑）尚未合并上游、当前分发包不含，KeyBonk 不依赖，等合并后再启用。
- 递归目录遍历：内建是否直接支持，否则用 `执("ls -R")` 或 FFI（M1 实测）。
- 无 Windows 预编译 raylib 库，Windows 回归需另编，本期不处理。
- 音频库全局静音/音量为占位，KeyBonk 静音必须留在调用层判断，切勿依赖库接口。
